# Plan: Script to Mint Long-Lived API Keys Outside Docker for MCP

## Context
User wants a host-side script (runs **outside** honcho docker containers) to mint long-lived API keys for MCP access without OAuth. Current MCP stdio path (`mcp/src/stdio.ts:8`, `mcp/honcho-mcp-stdio:5`) uses `HONCHO_API_KEY` env var defaulting to `"local-dev"`; production needs a real JWT signed with `AUTH_JWT_SECRET`.

Key discovery: `scripts/generate_jwt.py` **already implements this**. It mints scoped JWTs via `src/security.py:create_jwt(JWTParams)` with flexible durations (`--expires 1y`, etc.), runs outside docker using `AUTH_JWT_SECRET` from env/.env/config.toml, no DB required. This plan reuses that machinery rather than rebuilding it, adding MCP-specific ergonomics.

## Decision
**Primary: Enhance `scripts/generate_jwt.py` for the MCP/long-lived use case. Add thin alias `scripts/mint_api_key.py` only if explicit discoverability is required.**

Rationale:
- `scripts/generate_jwt.py:1-148` already handles `t`, `exp`, `ad`, `w`, `p`, `s` via `JWTParams`, duration parsing (`1y` = 365d), scope validation (`--peer`/`--session` require `--workspace`), `create_jwt` error when `AUTH_JWT_SECRET` missing (`src/security.py:78`), and `format_datetime_utc` for `exp`.
- `src/security.py:33-82` – stateless JWT, no DB table, HS256, `JWT_SECRET` from `src/config.py:698-708` (`AuthSettings`, precedence `init > env > .env > toml > secrets > defaults`).
- `src/routers/keys.py:30` – `POST /v3/keys` requires admin JWT + DB; host script avoids chicken-and-egg by signing directly.
- Risk of new script: duplicates logic, drifts from `verify_jwt`/`scope_requires_workspace` invariants.

If stakeholder insists on new file name for discoverability, make `scripts/mint_api_key.py` a 15-line wrapper that imports/re-exports `generate_jwt.main` with MCP-friendly defaults.

## Changes

### 1. `scripts/generate_jwt.py` (in place)
- Add `--mcp` convenience flag (optional but recommended): shorthand for long-lived MCP key. e.g. `--mcp` ≡ `--workspace openclaw --expires 1y` (respect explicit `--workspace`/`--expires` if also passed). Prints `export HONCHO_API_KEY=<token>` line + `HONCHO_API_URL` hint.
- Add `--format {text,raw,env,json}` (backward-compat: `--print-only` → `raw`). `env` prints `HONCHO_API_KEY=...` directly pasteable into MCP config; `json` returns `{"token": "...", "scope": ..., "expires": ...}`.
- When `AUTH_JWT_SECRET` missing, print actionable error listing sources checked: `AUTH_JWT_SECRET` env, `.env`, `config.toml [auth] JWT_SECRET`, plus `uv run python scripts/generate_jwt_secret.py --print-only`.
- If `--mcp` or long expiry (`>90d` or `1y`), print warning: "Long-lived token – not revocable without rotating JWT_SECRET. Prefer shorter expiry + re-mint if possible."
- Keep scope checks (`src/security.py:84-104` invariant): reuse existing `if (args.peer or args.session) and not args.workspace` guard; optionally call `scope_requires_workspace` for single source of truth.

### 2. `scripts/mint_api_key.py` (only if alias desired)
- Shebang `#!/usr/bin/env uv run python`, path shim `sys.path.insert(0, ...)`, then `from scripts.generate_jwt import main` or thin argparse that sets defaults (`workspace=openclaw`, `expires=1y`) and delegates. No duplicated JWT logic.
- Add to help: "Convenience alias for `generate_jwt.py --mcp`. See `generate_jwt.py --help` for full options."

### 3. `mcp/README.md` + `README.md` + `.env.template`
- Document: `uv run python scripts/generate_jwt.py --workspace openclaw --expires 1y` (or `--mcp`) → `export HONCHO_API_KEY=<token>` → `HONCHO_API_URL=http://127.0.0.1:8000 honcho-mcp-stdio`.
- Note: after minting, restart/reload MCP client so new env is picked up.

### 4. No DB, no migration, no new dependency
- Stays stateless; no `api_keys` table. DB only needed if later adding peer-alias resolution via `src/identity.resolve_peer_id` – out of scope (current script uses literal `p` claim; alias resolution happens at auth time in `src/security.py:246-258`).

## Alternatives Considered
- **New standalone `scripts/mint_api_key.py` with duplicated JWT logic**: Rejected – duplicates `generate_jwt.py` and risks scope-invariant drift.
- **API-call script (`POST /v3/keys`)**: Rejected – requires running containers + bootstrap admin token; contradicts "outside docker" requirement.
- **`honcho-cli` integration**: Viable follow-up, but host-side `scripts/` covers immediate need without packaging.

## Risks / Notes
- Secret must match deployed api/deriver containers; host `.env`/`config.toml` vs container mount divergence will produce invalid tokens – document `AUTH_JWT_SECRET` source of truth (`/srv/services/honcho` / `/opt/homelab/compose.yaml` bind-mount).
- Long-lived JWTs are not revocable statelessly; rotating `AUTH_JWT_SECRET` invalidates all tokens. Call out in docs.
- `scripts/generate_jwt.py` duration `1y` = 365 days (`DURATION_UNITS` line 40). No leap-year nuance – acceptable.
